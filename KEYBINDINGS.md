# wp keybindings

Generated by `tools/gen_keybindings.py` from the tables in `crates/wp/src/keymap.rs`. Every command is also reachable from the palette (`Ctrl+Shift+P` modern, `Ctrl+K` classic), which shows these keys. Override any binding in `~/.config/wp/config.toml` under `[bindings]`, e.g. `"ctrl+shift+b" = "bold"`; bind a key to `""` to unbind it.

Modified F-keys need a terminal that reports them (most do; the kitty keyboard protocol is used where available). On macOS set your terminal's Option key to act as Meta/Alt for `Alt+…` bindings.

## Modern

Selected with `keymap = "modern"` (the default). Movement and deletion follow emacs / macOS readline conventions: `Ctrl+F/B/N/P/A/E`, `Alt+F/B`, `Ctrl+D/H/K/U`, `Alt+D`, `Ctrl+W`/`Alt+W`/`Ctrl+Y`. All Classic bindings above remain active underneath; the rows below are added on top and win on conflict (`Esc` cancels rather than starting a repeat count, `F1` is help, `F3` is find-next, and the palette is `Ctrl+Shift+P` because `Ctrl+K` is kill-line). On macOS set the terminal's Option key to Meta for `Alt+…`.

### Cmd layer (macOS)

Part of the modern map. Delivered only by terminals that report the Cmd key through the kitty keyboard protocol (Ghostty, kitty, WezTerm); the terminal's own Cmd shortcuts take precedence — in Ghostty, free one with e.g. `keybind = cmd+k=unbind`. Ghostty also translates `Cmd+Backspace`, `Cmd+←`, `Cmd+→` into `Ctrl+U`, `Ctrl+A`, `Ctrl+E` by default, which the modern map handles the same way. Run `wp --probe-keys` to see what your terminal sends.
